# 数据与标注（组员 A）

你负责把**照片**变成模型能吃的 **`images/` + `masks/`**，再切成 train/val/test。
你的产出是组员 B 和组长的唯一输入，所以规则要稳：**改类别前先在群里通知全组**。

## 目录

```text
data/
  raw/                  # 原始照片（git 忽略，不进仓库）
  exports/              # 标注产物，下游只读这里
    images/xxx.jpg
    masks/xxx.png       # 单通道 uint8：0 背景，1..5 类别，255 ignore
  annotations/          # Label Studio 原始导出（git 忽略）
  splits/               # 由 scripts/split_dataset.py 生成
  categories.yaml       # 类别清单，唯一真源
```

## 你要交的四样东西

| 交付 | 路径 | 谁消费 |
|---|---|---|
| 自采照片 | `data/raw/<场景>_<日期>/` | 只有你自己 |
| 标注产物 | `data/exports/images/` + `data/exports/masks/` | 组长验收 |
| 数据集划分 | `data/splits/{train,val,test}/` | 组员 B 训练、你自己评测 |
| 指标结果 | `outputs/*_metrics.json` | 组长做对比表 |

## 照片格式要求

- 格式：`.jpg`（首选）或 `.png`。不要 iPhone 默认的 `.heic`，不要 `.raw` / `.dng`。
- 尺寸：保留手机原图，或统一缩到长边 1024-2048；同一批不要混用横竖比。
- 命名：`<场景>_<日期>_<序号>.jpg`，例如 `canteen_20261020_001.jpg`。
- 拍摄：不要滤镜、不要美颜、不要裁剪拼接；同一盘菜不要连拍几十张凑数。
- 不要拍人脸。
- 一张照片里尽量有 3-8 个可标注的食物实例 —— 一张图多个 mask 才划算。
- 收图后先过一遍：糊的、重复的、只拍到桌面的直接删。

## 类别体系

类别定义以 `data/categories.yaml` 为准，本文件只做解释。

- `0` 背景；`1-4` 是**要评测的目标类**；`5 other` 是兜底；`255 ignore` 完全不计分。
- 每类建议 40-60 张真实照片，先跑通闭环再扩容。

### 4 类之外的食物

`meat` / `fish` / `vegetable` / `rice` 是**我们要评测的目标类**，不是「照片里允许出现的全部东西」。
食堂打菜必然会混进鸡蛋、豆腐、土豆丝、汤、水果，规则是：

- 明显是食物、但不属于 1-4 类 → 标 `5 other`。
- 不是食物（餐具、包装袋、饮料瓶、纸巾、桌布、桌面）→ 不标，当背景 0。
- **绝不要把「其他食物」当背景标。** 那等于告诉模型「土豆丝是背景」，部署时它就会把土豆丝抠成背景 —— 那不是模型的失败，是标注教出来的。
- 混合菜（青椒炒肉丝、番茄炒蛋）不要硬拆成「肉」+「菜」两块，整份按主导属性归一类，说不清就标 `other`。
- 同一道菜在所有照片里必须归同一类。对照表直接写在本节下面：

| 菜名 | 类别 |
|---|---|
| 红烧肉 | meat |
| 清蒸鱼 | fish |
| 炒青菜 | vegetable |
| 米饭 | rice |
| 番茄炒蛋 | other |

> 上表是示例，按你们真实拍到的菜改。

### 什么时候该加新类别

- 某类食物在你们数据里占比超过 10%（比如鸡蛋、土豆）→ 别塞 `other`，直接加成类别 6。
- `other` 占比超过 20% → 说明类别体系选错了，要重新讨论（例如改成「主食 / 荤菜 / 素菜」，而不是按食材分）。

### 评测口径（写报告时必须说清）

- 当前脚本口径：忽略 `0` 背景和 `255 ignore`，对其余前景类取平均。
- 若报告要「主指标只报 1-4 类，`other` 单独一栏」，到结果阶段再按类拆分。
- `255 ignore` 只在真的说不清时用，不要批量打 255 当偷懒。

## 标注取舍规则

核心原则：**不追求标全，追求标得一致**。同一张图换个人重标一遍，结果应该基本一样。

- 上限：一张图最多标 15 个实例。超过就按像素面积从大到小取前 15 个，其余不标。
- 下限：可见面积不到整图的 0.5%，或长 / 宽任一边小于 20px 的，不标。
- 遮挡：被别的食物压住、可见部分不到一半的，不标。
- 拿不准：标成 255（ignore），评测时自动排除，不算标错。
- 粘连：两个食物真的糊在一起分不开时，只标可见轮廓，不要脑补边界。
- 价值下限：一张图连 3 个实例都凑不出 → 留作「稀疏 / 失败样本」，别塞进主训练集。
- 谁标：同一张图的所有 mask 必须由**同一个人一次标完**。两个人分着标同一张图，边界风格不一致会污染数据。

操作上：Label Studio 里**没画到的区域自动算背景 0**，所以「不标」就等于「当背景」，不需要额外操作。

## 标注步骤

```bash
# 1. 启动 Label Studio
pip install label-studio
label-studio start

# 2. 用 brush / rectangle 画 mask，导出 PNG，文件名和图片同名
#    <img_id>.jpg  <->  <img_id>.png
#    图片放 data/exports/images/，mask 放 data/exports/masks/

# 3. 把 mask 规整成 0..5 类别（原始导出会备份成 <name>_raw.png，可重复执行）
python scripts/convert_masks.py --src data/exports/masks --dst data/exports/masks

# 4. 划分 7:1:2
python scripts/split_dataset.py --data-dir data/exports --out data/splits
```

> **划分必须按图片切。** 同一张图的 mask 不能一部分进 train、一部分进 test，否则是数据泄漏，指标会虚高。
